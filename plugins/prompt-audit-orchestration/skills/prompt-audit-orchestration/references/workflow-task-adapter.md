# On-demand Role Adapter: Workflow

This adapter defines Workflow's scope and write authority. Use the main audit
Skill for coordination and evidence. Select the lifecycle profile and
publication owner for the actual Prompt or Skill.

## Workflow-purpose scope

The Workflow domain follows the primary purpose that a surface serves rather
than its file type or directory. Within the coordinator-resolved causal scope,
audit current local and shared reusable non-learning Skills and local prompts,
instructions, controls, and navigation surfaces whose behavior materially shapes
a model workflow. For a
full Workflow-domain run, discover current identities from canonical owners and
actual consumers and cover these semantic families:

- user-owned reusable non-learning repository and host-native Skills, together
  with their declarations, projections, registration, publication, and local consumers;
- current user-maintained local common/global and project instruction systems,
  including canonical sources, host adapters, workspace fields, and consumers;
- current local non-learning model-facing instruction surfaces under Document
  Misc, including workspace navigation, language and Markdown presentation
  policies, user-manual authoring instructions, native prompt publication and
  readback rules, AGENTS, injected shared-static workflow instructions, policy
  prose, and navigation; and
- another current or future non-learning document workflow's model-facing
  instructions and controls when its actual consumer and semantic, canonical,
  publication, authority, and safety owners place it in the resolved scope.

For a bounded run, cover the material slice of these families and use the main
Skill's scope rule for exclusions.

## Evidence and target-specific repair boundaries

Apply the main Skill's dispositions to the actual semantic, source, and
publication owners.

For an affected hosted consumer of a shared Workflow source, establish the
actual mapping and coordinate one writer with Hosted when selected. Follow the
lifecycle's delivery method for package closure and hosted consumer readback.
Check connected local execution only when affected. Report the consequence
and any remaining hosted convergence gap.

Classify model-facing documents under general document collection or document and memory store by their
actual consumer, not their location or filename. Local general instructions
remain Workflow targets; hosted common/global and non-learning Project prompts and Hosted-specific
connector/operator instructions belong to Hosted. For one canonical source feeding
both consumers, retain its actual owner, coordinate one writer, and check both
consumers' material consequences under the main Skill. Repair each source only
through its actual owner.
Generated Prompt Map or local-prompt projections are evidence rather than
editable sources; return their repair to the repository source and current Skill
or generator owner. Retained Artifacts, Plans, user-input provenances, historical design
records, available activity history observations, personal memory records, and ordinary
document data are evidence rather than prompt-normalization targets. An active
producing workflow may still own an exact current mutable record.

Imported upstream Skill bodies follow their upstream or explicit overlay owner.
Bundled, provider-owned, system, externally owned Project, or unresolved Hosted-only
Skills are cross-owner or evidence-only targets rather than direct repairs. A
pre-existing Prompt Map, sync, UI, or configuration incident is evidence-only
unless the user separately requested incident repair.

Dedicated learning-method Skills and prompts, Course controls, and connected local workspace
instructions belong to the Learning adapter. They are excluded from Workflow's
target inventory. Workflow may inspect them as material evidence and report the
exact dependency, but it does not audit or repair them on Learning's behalf.
Likewise, Learning may inspect Workflow targets but cannot repair them. A
learning-relevant clause does not transfer a local common/global target out of
Workflow; transfer requires a dedicated Skill or prompt whose current primary
purpose is learning. Dedicated learning-purpose Hosted Project Instructions,
including learning, remain Learning-owned; a learning-related clause alone does not
transfer a common/global instruction source.

Saved local scheduled, recurring, or deferred Task prompts and dedicated
task-purpose Skills belong to Saved Task. Local and shared reusable non-learning
Skills and local common/global instructions remain Workflow targets when a
Task invokes them; hosted common/global and non-learning Project instructions
and Hosted-specific methods
retain Hosted ownership.
Workflow may inspect the Task's material effect and exact dependency; Saved Task
must likewise inspect material downstream effects of Workflow sources and route
shared-source findings to Workflow. Follow the main Skill's overlap and
single-writer contract; a single-domain request does not automatically launch
a peer or transfer source responsibility.

Hosted Scheduled Task prompt content, native fields, and recovery mirrors remain
maintained through the user's Scheduled Task Project under its current Project
Instructions and explicit Task request. An on-demand Workflow run may read them
as evidence and report an exact dependency, but it does not mutate them. Current
local/shared general task-authoring methods remain Workflow audit targets;
hosted common/global and non-learning Project prompts and independently owned
Hosted-specific reusable
authoring methods follow the Hosted adapter. Auditing those methods does not
authorize changes to any
Task configuration or recovery mirror.

## Working and return boundary

Return the examined scope, material exclusions, owned changes with readback
and relevant behavior evidence, cross-owner consequences, and any blocker.
Account for each target family above in a full-domain result.
