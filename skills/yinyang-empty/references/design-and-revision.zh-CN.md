# 工作模型的形成与修订

<a id="形成自己的哲学与个人模型"></a>

工作模型给语言模型提供合作所需的背景，说清你想发展什么、你怎样参与、希望模型怎样帮忙、有哪些条件，以及安排怎样改变。本篇说明怎样写出、核对和修订六份工作描述。[《实践指南》](creation-method.zh-CN.md)说明这项工作怎样进入更广的实践。

## 基于实际材料形成情境化版本

选一项实际活动，让写作有明确的用途。请模型从已有材料中找回相关的原话、事件和可观察的结果。重要推断要留下足够的语境，使下次合作时能够看出它有什么根据、在什么条件下适用、会带来什么不同。如果有用的解释尚未确定，写清什么证据可以区分几种解释。[《六份描述的共同写作要求》](formation/shared.zh-CN.md#从可归属的材料写起)说明各种材料各能支持怎样的结论。

把模型写成六份相连的描述。六份描述对同一实践回答不同的问题。

| 工作描述 | 要回答的问题 |
| --- | --- |
| [取向](formation/orientation.zh-CN.md) | 当事人看重什么、想发展什么？这些方向应当怎样指引工作？ |
| [个人](formation/person.zh-CN.md) | 对当事人的目的、参与、能力和条件，有哪些会改变合作的有根据理解？ |
| [伙伴](formation/counterpart.zh-CN.md) | 实际模型在当前条件下能做什么？希望它贡献什么？哪些判断需要核对？ |
| [关系](formation/relationship.zh-CN.md) | 双方怎样一起创作、审查、委派和纠正？一方的贡献怎样让另一方能够接续？ |
| [环境](formation/environment.zh-CN.md) | 哪些指令、工具、界面和物质条件使合作成为可能？怎样核对它们的实际作用？ |
| [修订](formation/revision.zh-CN.md) | 新的目的、异议或观察到的结果，怎样改变有关理解与安排？又怎样核对实际改变？ |

拟定或实质修订综合问题前，联系当前描述和有关来源，完整看过[如何写六份描述](formation/overview.zh-CN.md)。每个问题都保留完整的范围。同一份材料可以进入几份描述，在不同描述里发挥不同作用。让模型取得足以写清这些关系的上下文。模型直接写作时，六份描述可以保存在六份私人文件中。使用工具综合时，也要让工作的模型能取得每一份完整描述。

### 写下会改变合作的关系

例如，读者说「那个问题之后，我就失去了思路」。先找回当时的问题，看看它在阅读的哪一步打断了什么。个人描述可以写这种中断在当时条件下怎样影响持续阅读。伙伴描述可以写哪些实现选择模型能自行判断、哪些不确定之处值得问。关系描述可以写什么时候集中提问、提问后怎样帮读者接回原来的阅读。每份描述各有贡献。把体验报告与拟议的解释写清楚，下一次遇到类似情形才有机会纠正这份理解。

请模型围绕这些关系写出完整可读的描述，在会影响判断的地方保留相关原话、时间或来源位置，也保留人在不同活动中选择不同参与方式的空间。比如，为了学习可以亲手做一次实现，需要交付结果时可以把类似的实现交给模型。[《六份描述的共同写作要求》](formation/shared.zh-CN.md#按实际用途写作)说明如何在凝练时保留以后用得上的条件和关系。

## 通过修订使六份描述融贯

把六份完整描述联系起来，对照重要来源和实际结果阅读。比较各份说的是哪项活动、写下的是谁的判断、哪些时段和条件适用，以及各份指出的后果怎样接得上。体现在材料中的分歧和未知可以保留。两份描述对同一处境作出不同判断时，回到原始根据。一份描述的解释可以提示另一份有哪些依赖；检验时还要回到原材料。

前提变了，就沿着它在各份描述中的作用检查。例如，当事人为学习而选择更多参与，取向写明学习目的，个人写下参与的变化，伙伴写清现在怎样帮忙。关系可以写何时交还主动权，环境可以写怎样使交接成为可能，修订可以写怎样判断这种参与有没有帮助。把相关段落改到能够在使用中接起来。如果不一致来自对来源的理解或综合指引，按[六份描述的融贯检查](formation/revision-method.zh-CN.md#检查六份描述的融贯)更新有影响的地方，然后把受影响的描述放回整体再读一遍。

## 用实际工作修订描述

<a id="在实际尺度上评估结果"></a>

让模型读取六份完整描述，带着它们做一件实际工作。检查它取得了哪些内容、怎样理解其中涉及的关系，以及活动中发生了什么。使用记忆或综合工具时，也查看综合后的完整描述，把重要推断追回到支持它的材料。材料能取得、解释有根据、工作做成、人的参与有改善，各有各的证据。

<a id="根据不断变化的相遇进行修订"></a>

把不合之处追到需要改变的理解。新的请求可能指出一个例外，缩小一项判断的适用范围，动摇原来的解释，或改变工作的方向。较早的说法和观察保留在其来源中。

比如，原先的关系描述可以写「由模型负责实现上的选择，让本人能够接着阅读」。一次阅读中，模型自行做了小调整，本人得以接着读。后来本人想学习制作阅读工具，请模型把第一个会影响做法的选择留给自己练习。

修订后的描述可以写「任务以交付可用结果为目的时，模型自行决定可逆的实现细节，集中提问会影响结果的事项。任务以学习实现为目的时，模型在第一个会改变做法的选择前停一下，让本人试着决定」。两次活动为同一种合作关系说明了不同的适用条件。下一次跟模型做事时，可以查看它能不能根据这段描述判断当前是哪一种活动，并据此配合。

改动涉及多份描述或需要补充证据时，按[实际工作的修订方法](formation/revision-method.zh-CN.md#确定修订范围与联动)处理。如果同一种问题反复没能被发现，就改进这些描述收集根据和吸收纠正的方法，再从后续工作中检验改进。
